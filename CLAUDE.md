# CLAUDE.md — Shopify Theme Development

## Project Stack

This is a **Shopify Online Store 2.0** theme project using:

- **Tailwind CSS v4** — via CLI build step (NOT CDN in production)
- **Alpine.js v3** — via CDN `<script>` tag (lightweight, no build step needed)
- **Flowbite v4** — via CDN for CSS + JS (component library on top of Tailwind)
- **Shopify Liquid** — primary templating language
- **Vanilla JS / Web Components** — for Shopify-native interactivity

## Architecture Overview (Horizon Theme)

This project uses **Shopify's Horizon theme** as the base — NOT Dawn. Horizon is a
new-generation theme that uses **theme blocks** (`/blocks` directory) as first-class
reusable, nestable components. This is fundamentally different from Dawn's section-only model.

```
theme-root/
├── assets/                      ← Static assets (CSS, JS, images, fonts)
│   ├── tailwind-input.css       ← Tailwind source (directives + custom CSS)
│   ├── application.css          ← Tailwind compiled output (DO NOT EDIT)
│   ├── alpine-stores.js         ← Alpine.js global stores & reusable data
│   ├── theme.js                 ← Custom vanilla JS / web components
│   └── [horizon assets]         ← Horizon's own CSS, JS, SVGs — DO NOT DELETE
├── blocks/                      ← Theme blocks (reusable across sections, nestable up to 8 levels)
│   ├── button.liquid
│   ├── heading.liquid
│   ├── image.liquid
│   ├── text.liquid
│   ├── _private-block.liquid    ← Underscore prefix = private (only usable where explicitly allowed)
│   └── [your custom blocks]
├── config/                      ← Global theme settings (settings_schema.json, settings_data.json)
├── layout/
│   └── theme.liquid             ← Top-level layout — CDN scripts loaded here
├── locales/                     ← Translation files
├── sections/                    ← Full-width page sections
├── snippets/                    ← Reusable Liquid fragments
├── templates/                   ← JSON templates combining sections
├── .cursor/rules/               ← Horizon's AI coding rules (if present)
├── tailwind.config.js           ← Tailwind config (content paths, theme extensions)
├── package.json                 ← Dev scripts (tailwind watch + shopify dev)
├── .shopifyignore               ← Ignore node_modules, source CSS, configs
└── CLAUDE.md                    ← This file
```

### Horizon vs Dawn — Key Differences

- **`blocks/` directory**: Theme blocks are defined as standalone `.liquid` files, reusable across ANY section. Dawn only had section-level blocks defined inside each section file.
- **Nestable blocks**: Theme blocks can nest up to 8 levels deep. Use `{% content_for 'blocks' %}` to render child blocks inside a parent block.
- **`@theme` block type**: Sections use `"blocks": [{"type": "@theme"}]` in their schema to accept any theme block. Sections use either theme blocks OR section blocks, never both.
- **Private blocks**: Prefix filename with `_` (e.g., `_slide.liquid`) to make a block private — only usable where explicitly listed in a parent's schema.
- **CSS variables for settings**: Horizon uses CSS custom properties (`--gap`, `--color`, etc.) for single-property settings, CSS classes for multi-property settings.
- **`{% stylesheet %}` tag**: Horizon uses scoped stylesheets inside blocks/sections. These are automatically deduplicated by Shopify.
- **Server-rendered philosophy**: HTML is rendered by Liquid on the server. Client-side JS is used sparingly as progressive enhancement.
- **Progressive enhancement over polyfills**: Leverage modern browser features, degrade gracefully.

## Critical Rules

### Tailwind CSS

- **Source file**: `tailwind-input.css` in project root (or `src/tailwind-input.css`)
- **Output file**: `assets/application.css` — this is what Liquid references
- **NEVER edit `assets/application.css` directly** — it is regenerated by the Tailwind CLI
- Content scanning is configured in `tailwind.config.js` to scan all `.liquid` files
- Use Tailwind v4 syntax: `@import "tailwindcss"` (NOT the old `@tailwind base` directives)
- For Flowbite integration: include `@plugin "flowbite/plugin"` and `@source "../node_modules/flowbite"` in the CSS source
- Custom theme extensions (colors, fonts, spacing) go in `tailwind.config.js` under `theme.extend`
- Use `@apply` sparingly — prefer utility classes directly in Liquid markup
- When adding new Tailwind classes to Liquid files, the watch process auto-rebuilds

### Alpine.js

- Loaded via CDN in `theme.liquid` `<head>` with `defer` attribute
- Version pinned: `https://cdn.jsdelivr.net/npm/alpinejs@3.14.9/dist/cdn.min.js`
- Use `x-data` directly on HTML elements for component-scoped state
- Use `Alpine.store()` in `assets/alpine-stores.js` for shared global state (cart, modals, etc.)
- Alpine.js replaces the need for most jQuery — use it for: toggles, dropdowns, tabs, modals, form validation, show/hide logic
- DO NOT use Alpine.js for things Shopify handles natively (variant selection via web components, cart AJAX via Fetch API)
- Always add `x-cloak` + corresponding CSS `[x-cloak] { display: none !important; }` to prevent FOUC

### Flowbite

- Loaded via CDN in `theme.liquid`:
  - CSS: `https://cdn.jsdelivr.net/npm/flowbite@4.0.1/dist/flowbite.min.css`
  - JS: `https://cdn.jsdelivr.net/npm/flowbite@4.0.1/dist/flowbite.min.js` (before `</body>`)
- Flowbite provides pre-built components: modals, dropdowns, tooltips, carousels, accordions, tabs, etc.
- Flowbite JS uses `data-*` attributes for interactivity — these work alongside Alpine.js
- When Flowbite and Alpine.js overlap (e.g., both can handle modals), prefer Flowbite's `data-modal-*` attributes for simple cases, Alpine.js `x-data` for complex state-dependent cases
- Reference Flowbite docs: https://flowbite.com/docs/components/
- Use Flowbite MCP in Claude Code for component lookups (see MCP section below)

### Liquid Conventions (Horizon)

- **Theme blocks** go in `blocks/`, sections in `sections/`, snippets in `snippets/`
- Block filenames: `block-name.liquid` (kebab-case). Private blocks: `_block-name.liquid`
- Section filenames: `section-name.liquid` (kebab-case)
- Every section and block MUST have a `{% schema %}` block
- Sections that accept theme blocks use `"blocks": [{"type": "@theme"}]` in their schema
- To accept specific blocks only: `"blocks": [{"type": "heading"}, {"type": "text"}, {"type": "@app"}]`
- Render child blocks inside a parent with: `{% content_for 'blocks' %}`
- Use `{{ 'application.css' | asset_url | stylesheet_tag }}` in theme.liquid to load Tailwind output
- Use `{% stylesheet %}` inside blocks/sections for scoped CSS (auto-deduplicated by Shopify)
- Use CSS variables for single-property settings:
  ```liquid
  <div style="--gap: {{ block.settings.gap }}px">
  {% stylesheet %}
  .my-component { gap: var(--gap); }
  {% endstylesheet %}
  ```
- Use CSS classes for multi-property settings (e.g., layout modes)
- Use Shopify's native `{{ content_for_header }}` and `{{ content_for_layout }}` — never remove these
- Prefer Liquid filters over JS for data formatting (e.g., `| money`, `| date`, `| image_url`)
- For custom additions, prefer creating NEW files over editing Horizon's existing files to preserve upgradeability
- Keep custom CSS in a separate `assets/custom.css` when not using Tailwind for specific overrides

### JavaScript

- Vanilla JS preferred over jQuery
- Web Components for complex interactive elements (product forms, cart drawers)
- Alpine.js for UI state (menus, accordions, filters, modals)
- Flowbite JS for pre-built interactive patterns
- Load order in theme.liquid:
  1. Tailwind CSS (in `<head>`)
  2. Flowbite CSS (in `<head>`)
  3. Alpine.js CDN (in `<head>` with `defer`)
  4. Custom JS files (before `</body>`)
  5. Flowbite JS (before `</body>`)

### Performance

- Tailwind CSS is purged at build time — only used classes ship to production
- Alpine.js is ~17KB gzipped — acceptable for the interactivity it provides
- Flowbite JS is loaded from CDN with browser caching
- Lazy-load images using Shopify's `| image_url` with `loading="lazy"`
- Use `<link rel="preconnect" href="https://cdn.jsdelivr.net">` in theme.liquid head

## Development Workflow

### Start development (two parallel processes):

```bash
npm run dev
```

This runs concurrently:
1. `shopify theme dev` — Shopify local dev server
2. `npx @tailwindcss/cli -i ./tailwind-input.css -o ./assets/application.css --watch` — Tailwind watcher

### Deploy:

```bash
npm run build    # One-time Tailwind production build (minified)
shopify theme push
```

## Common Patterns (Horizon)

### Theme Block with Alpine.js (blocks/toggle-content.liquid)

```liquid
<div x-data="{ open: false }" class="py-4">
  <button @click="open = !open" class="flex items-center gap-2 text-left w-full">
    <span class="font-medium">{{ block.settings.title }}</span>
    <svg :class="open && 'rotate-180'" class="w-4 h-4 transition-transform" fill="none" stroke="currentColor" viewBox="0 0 24 24">
      <path stroke-linecap="round" stroke-linejoin="round" stroke-width="2" d="M19 9l-7 7-7-7"/>
    </svg>
  </button>
  <div x-show="open" x-collapse x-cloak class="mt-2 text-gray-600">
    {{ block.settings.content }}
  </div>
</div>

  "settings": [
    {
      "type": "text",

    },
    {
      "type": "richtext",
      "id": "content",
      "label": "Content"
    }
  ],
  "presets": [
    {
      "name": "Toggle Content"
    }
  ]

{% endschema %}
```

### Cart AJAX with Alpine.js Store

```javascript
// assets/alpine-stores.js
document.addEventListener('alpine:init', () => {
  Alpine.store('cart', {
    items: [],
    count: 0,
    loading: false,

    async fetch() {
      this.loading = true;
      const res = await fetch('/cart.js');
      const data = await res.json();
      this.items = data.items;
      this.count = data.item_count;
      this.loading = false;
    },

    async add(variantId, quantity = 1) {
      this.loading = true;
      await fetch('/cart/add.js', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ id: variantId, quantity })
      });
      await this.fetch();
    }
  });
});
```

## Horizon Upgradeability Rules

When customizing a Horizon-based theme, follow these rules to stay upgradeable:

1. **Create NEW block/section/snippet files** instead of editing Horizon's existing ones
2. **Put custom CSS in `assets/custom.css`** (or via Tailwind) rather than editing Horizon's CSS files
3. **Put custom JS in `assets/theme.js`** rather than editing Horizon's JS files
4. **Use theme.liquid sparingly** — prefer app embed blocks for global scripts when possible
5. **Track upstream**: `git remote add upstream https://github.com/Shopify/horizon.git`
6. **Document all custom changes** in a changelog or README

## What NOT To Do

- DO NOT use Tailwind CDN (play CDN) in production — it ships the entire framework unoptimized
- DO NOT mix jQuery with Alpine.js — pick one reactivity model
- DO NOT put `node_modules` in Shopify assets
- DO NOT edit `assets/application.css` by hand
- DO NOT use `@tailwind base; @tailwind components; @tailwind utilities;` — that's v3 syntax. Use `@import "tailwindcss"` for v4
- DO NOT load Alpine.js as a module in Shopify themes — use the CDN script tag
- DO NOT forget to run the Tailwind build before deploying (`npm run build`)
